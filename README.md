# subwatch

> **在你被自动续费扣款之前提醒你：这笔钱要扣了，还要留吗？**

一个 Windows 桌面小工具。它不做订阅管理——"我订了哪些服务"支付宝和微信已经免费给你看了。
它做的是平台**没做**的那三件事：

1. **扣费前的主动提醒** —— 自动续费页面只有你主动打开才可见，它不会提前三天问你"这 25 元还留吗"
2. **跨平台合并** —— 你的订阅散落在 Apple、微信、支付宝、信用卡、年费服务（域名/VPS）里，没有任何单一平台能给你全貌
3. **试用期到期提醒** —— "首月 1 元、次月自动续 25 元"这一块，系统完全不提醒

## 它不做什么（重要）

- **不会替你取消订阅。** 中国的自动续费散落在支付宝/微信/Apple/运营商/银行，没有开放银行接口，
  第三方程序在技术上做不到代客取消。subwatch 给的是**核对过的退订路径**，然后帮你记住处理进度。
- **不联网、不上传。** 所有数据存在你自己的电脑上（`%APPDATA%\subwatch\data.json`）。
  这既是隐私考虑，也是这个产品该有的立场——你的消费记录不该离开你的机器。
- **不给你理财建议。** 它只做信息聚合和提醒。

## 安装

### 方式一：安装包（推荐）

1. 下载 `subwatch-0.1.0-x64.exe`
2. 双击运行

> ⚠️ **Windows 会弹出蓝色的"Windows 已保护你的电脑"**
>
> 这是因为这个应用**没有购买代码签名证书**（一张证书 150–300 美元/年，个人开发者负担不起）。
> Windows 对没有签名的程序一律这样提示，与程序安全性无关。
>
> 继续安装的方法：点**「更多信息」** → 点**「仍要运行」**。
>
> 如果你不放心，可以下载 `subwatch-0.1.0-x64.zip` 绿色版，解压后看看里面的文件，
> 或者直接克隆仓库自己构建（见下方「技术栈与开发」）。

### 方式二：绿色版

下载 `subwatch-0.1.0-x64.zip`，解压到任意目录，双击 `subwatch.exe`。
不需要安装，不需要管理员权限。

> ⚠️ **如果双击没反应**：绿色版解压到某些目录（尤其是非系统盘）时，Windows 的
> AppContainer 权限会导致 Electron 直接退出。右键**「修复启动问题.bat」→ 以管理员身份运行**
> 即可修好。安装版不会有这个问题——这也是推荐用安装版的原因。

## 怎么用

1. **打开就能加**：首屏是常见订阅的网格（爱奇艺/腾讯视频/iCloud/百度网盘/域名/服务器…），
   点一下就加好了，不用填表单
2. **等提醒**：扣费前 7 天、3 天、1 天各提醒一次。当天打开会显示"今天要扣"
3. **收到提醒后**：点「退订」→ 里面有四个选项（告诉我怎么退 / 我已经退订了 / 还没退先记着 / 删除记录）
4. **想知道花了多少**：顶部就是月/年汇总，点「分享卡片」可以生成一张可复制的账单图

## 为什么提醒文案是那种语气

不是"XX 将于 3 天后续费"，而是：

> **腾讯视频 VIP 3 天后要扣 ¥25 · 你上次用它还是 200 天前 · 要留还是退？**

因为被自动续费扣钱的时候，人的情绪是**愤怒**，不是"想优化一下开支"。
这个工具站在你这边。

## 关于退订路径的准确性

`src/core/guides.js` 里的每条路径都标注了来源可信度：

- `official` —— 厂商官方帮助页/服务协议，附 source 链接
- `media` —— 权威媒体报道

**爱奇艺、哔哩哔哩、QQ音乐、网易云音乐这几家没有收录 App 内路径**——不是遗漏，
而是它们的官方站点和协议里**确实没有公布**可核对的取消入口（有的协议反而写"开通后不可退订"）。
这种情况我们会明确引导你去签约通道解约，而不是编一条路径让你白折腾。

如果你发现哪条路径过时了，欢迎提 issue。

## 技术栈与开发

```powershell
npm install
npm run verify     # 89 项单元测试 + 137 项渲染层校验 + 28 项交互演练
npm start          # 开发模式启动
npm run pack:win   # 打绿色版 zip；NSIS 安装包走 CI（见 docs/发布流程.md）
```

- Electron + 原生 HTML/JS（没有前端框架）+ JSON 文件存储（没有原生模块）
- `src/core/` 是纯函数业务逻辑，零依赖，可被 node 直接 require 并测试
- 代码注释里写的是「为什么」：为什么用 JSON 而不是 sqlite、为什么续费日要从锚点日推导、
  为什么退订只做指引不做代操作 —— 这些取舍都在对应文件的头部注释里

### 几个容易踩的坑（写在这里省得后面的人重复踩）

- **不要引 `better-sqlite3`**：原生模块在 Electron 里要 `electron-rebuild`，
  而本项目用 JSON 就够（几十条订阅的数据量），换来的是打包零工具链依赖
- **`npm ci` 不保证执行 electron 的 postinstall**：CI 上 `node_modules/electron/dist`
  可能不存在，需要显式跑一次 `node node_modules/electron/install.js`
- **不要用 PowerShell 的 `Set-Content -Encoding UTF8` 写含中文的文件**：
  会加 BOM，并且会把已有中文重新编码成乱码。`npm run verify` 里有检查会拦住
- **判断文件编码不要用 `Get-Content`**：PS 5.1 会用系统 ANSI 代码页读 UTF-8 文件，
  干净的文件在终端里会显示成乱码（这个坑踩过，差点去修一个没坏的文件）
- **续费日期必须从锚点日推导**：1/31 起算要依次落在 2/28、3/31，
  不能逐月累加漂移成 28 号。`test/renewal.test.js` 覆盖了这些边界
