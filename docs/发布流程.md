# 发布流程

> 面向你（维护者）。从"代码改完"到"别人能装上"的完整步骤。

---

## 一、首次：把本地仓库推到 GitHub

本地仓库已经准备好（有 git 历史、`.gitignore`、CI 配置），只差一个远端。

### 1. 在 GitHub 建一个空仓库

- 打开 https://github.com/new
- **Repository name**：`subwatch`
- **不要**勾选 "Add a README file"、".gitignore"、"license"（本地都有了，勾了会冲突）
- 可见性：**Public**（Release 下载和 CI 都需要；Private 也能用但下载要登录）
- 点 **Create repository**

### 2. 把本地仓库推上去

在项目目录执行（把 `你的用户名` 换成你的 GitHub 用户名）：

```powershell
git branch -M main                #  GitHub 现在的默认分支名是 main
git remote add origin https://github.com/你的用户名/subwatch.git
git push -u origin main
```

> 第一次推送会要求登录。GitHub 早已不支持密码，需要用 **Personal Access Token**：
> Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token，
> 勾选 `repo` 和 `workflow`，然后把它当密码粘贴。

### 3. 确认 CI 能跑

推上去后打开 `Actions` 标签页，应该能看到 `build-windows` 在跑（因为 workflow 支持手动触发）。
如果失败，看日志——大概率是 Node 版本或 `npm ci` 的问题。

## 二、每次发新版

### 1. 改版本号并提交

```powershell
# 在项目目录执行
# 改 package.json 里的 version，例如 0.1.0 → 0.1.1
npm run verify          # 必须全绿才能发
git add -A
git commit -m "chore(release): v0.1.1"
git push
```

**`npm run verify` 是硬门槛**：86 项单测 + 100 项渲染层校验 + 21 项交互演练。
任何一项红了都不要发版。

### 2. 触发 CI 打包

**这里有个容易搞混的地方：CI 的产物分两种，通往两个地方。**

| | 触发方式 | 产物在哪 | 谁能下载 | 有效期 |
|---|---|---|---|---|
| **artifact**（构建产物） | 任何一次运行 | Actions 运行页底部 | **只有登录的你** | 默认 90 天后清理 |
| **Release**（发布页） | 推 `v*` tag | 仓库 Releases 页 | **所有人，不用登录** | 长期 |

**发给同事朋友用，必须走 Release。** artifact 是给自己调试用的，别人点不开。

#### 方式 A：先试跑一次（不发布，只验证能不能打出来）

适合第一次用，确认 CI 配置没问题：

1. 打开仓库页 → 顶部 **Actions** 标签
2. 左侧点 **build-windows**
3. 右侧 **Run workflow** 下拉 → 选 `main` 分支 → 点绿色 **Run workflow**
4. 等 5–10 分钟，刷新页面，点进那次运行
5. 页面底部 **Artifacts** 区域会出现 `subwatch-windows`，下载解压就能拿到 `.exe` 和 `.zip`

> 注意：`workflow_dispatch`（手动触发按钮）只有在 workflow 文件已经存在于默认分支时才会出现。
> 所以推上去之后先刷新一次 Actions 页面。

#### 方式 B：正式发布（推荐，一步到位）

```powershell
git tag v0.1.0
git push origin v0.1.0
```

CI 会自动跑完验证 → 打 **NSIS 安装包**（`.exe`）和**绿色版**（`.zip`）
→ 把两个文件挂到 **Releases** 页，并自动创建 `v0.1.0` 这个 release。

等 Actions 跑完（约 5–10 分钟），去仓库的 **Releases** 页确认：

- `subwatch-0.1.0-x64.exe` ← 安装包（**推荐发给别人**，没有 ACL 问题）
- `subwatch-0.1.0-x64.zip` ← 绿色版（附带了 `修复启动问题.bat`）

Release 页的链接就是你要发出去的东西，形如：

```
https://github.com/你的用户名/subwatch/releases/latest
```

> 想撤回发布：删掉 tag 和 release 即可
> （`git push --delete origin v0.1.0`，再去 Releases 页删掉那条）。

### 3. 本地验证产物（**别省这一步**）

CI 打的包**务必下载到自己机器上装一次**再告诉别人。CI 能证明"打包过程没报错"，
**不能证明"装完能打开"**——这两件事在未签名的 Electron 应用上经常不一样。

重点确认：
- 安装版：能正常安装、装完双击能打开、托盘图标出现
- 绿色版：解压后双击能打开；打不开就跑 `修复启动问题.bat`

## 三、为什么要用 CI 打包，而不是本地打

本地打包在这个开发环境里受限（详见 `HANDOFF.md` §0.8）：

- `npm run pack:zip` **能用**，产出绿色版 zip（走的是自写的 `pack-portable.js`，绕开了 electron-builder）
- **NSIS 安装包打不了** —— electron-builder 有一个步骤必须 spawn 子进程并接管管道，当前沙箱禁止

而 NSIS **安装包才是首选分发形式**，因为：
> Electron 用受限令牌（AppContainer）启动渲染进程，该令牌必须能读程序自身所在目录。
> 装到 `%LOCALAPPDATA%\Programs` 时 Windows 会赋予正确权限，**天然没有这个问题**；
> 而绿色版解压到非系统盘等目录时可能缺少该权限，会直接崩溃。

CI 的 `windows-latest` 没有这个沙箱限制，能正常打出安装包。

## 四、分发时怎么跟人说

**一对一私聊，不要在工作群发。** 话术模板见 `docs/安装说明.md`（可直接复制）。

三条必须说到的：

1. **Windows 会提示「已保护你的电脑」** → 点「更多信息」→「仍要运行」
   （没买代码签名证书，150–300 美元/年；这与安全性无关）
2. **数据在你自己电脑上**，不联网、不上传
3. **"没用你直接删，不用回我"** —— 这句是有意的，让对方不必客气假装在用，你才能拿到真实反馈

渠道优先级（有实测依据）：

| 渠道 | 效果 | 备注 |
|---|---|---|
| 少数派 Matrix「开发者说」 | **最好**，一篇可带来 1.2 万阅读 | 可立即投，无需养号；禁止假扮第三方评测 |
| 垂直社区/周刊提及 | 单次跃升最大 | 有案例是阮一峰周刊收录当天 +278 star |
| V2EX「分享创造」 | 中等 | **新号要等 30 天**，营销内容须发「推广」节点 |
| 小红书 / 即刻 | **实测 ≈0 转化** | 不要买即刻的付费发布会（200+ 元换约 5 个用户） |

## 五、发版检查清单

发之前逐条打勾：

- [ ] `npm run verify` 全绿
- [ ] `package.json` 的 version 已更新
- [ ] `HANDOFF.md` 的"当前进度"一节已同步
- [ ] tag 已推（`git push origin vX.Y.Z`）
- [ ] CI 跑完，**Releases 页**（不是 Actions artifact）上有 `.exe` 和 `.zip`
- [ ] **自己下载安装包试装过一次，能打开**
- [ ] Release 说明里有 SmartScreen 提示
- [ ] `docs/安装说明.md` 里的文件名与新版本一致

## 六、遇到问题的排查入口

用户报"打不开"时，让他发这两样：

1. `%TEMP%\subwatch-boot.log` —— 早期启动日志（在 `app.whenReady()` 之前就开始写，
   能看出卡在哪一步）
2. `%APPDATA%\subwatch\boot.json` —— 启动报告（窗口、托盘、订阅数、Electron 版本）

这两个文件是开发时专门为排查这类问题加的，见 `HANDOFF.md` §0.4。

**最常见的两种"打不开"**：

| 现象 | 原因 | 解决 |
|---|---|---|
| 双击完全没反应 / 一闪而过 | AppContainer 权限（绿色版） | 跑 `修复启动问题.bat`（管理员）或改用安装版 |
| 弹蓝色「已保护你的电脑」 | 未签名 | 更多信息 → 仍要运行 |
